# Vibe Codingやってみた

## Vibe Codingとは

Andrej Karpathyが提唱した概念

> "There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."

- コードの詳細を気にせず「雰囲気」で指示
- AIに任せて結果だけ見る
- 動けばOK、細かいことは後で

## 従来のコーディングとの違い

| 従来 | Vibe Coding |
|------|-------------|
| 1行1行書く | 「こんな感じで」と伝える |
| エラーを自分で直す | 「エラー出たよ」と伝える |
| ドキュメント読む | 「〜したいんだけど」と聞く |
| 設計を考える | 動くものを作ってから考える |

## 実際にやってみた例

### 例1: 簡単なツール作成

```
ExcelをCSVに変換するスクリプト作って。
ファイルをドラッグ&ドロップで指定できるようにして。
```

### 例2: 既存コードの修正

```
このAPIのレスポンスにページネーション追加して。
他のAPIと同じ形式で。
```

### 例3: バグ修正

```
ログイン後にリダイレクトがおかしい。直して。
```

## 良かった点

- プロトタイピングが爆速
- 知らない言語/フレームワークでも書ける
- 面倒なボイラープレートを任せられる
- 「やりたいこと」に集中できる

## 注意点・落とし穴

### 1. 何が生成されたか把握しづらい

- 大量のコードが一気に生成される
- 後で読むと理解できないことも

### 2. 品質の担保

- テストは書かせる
- レビューは必要
- セキュリティは要注意

### 3. 学習機会の損失

- 自分で書かないと身につかない
- 基礎は別途学ぶ必要

### 4. デバッグが難しい

- 自分で書いてないコードのデバッグ
- 「なぜこうなってる？」が分からない

## どんな場面で有効か

- プロトタイプ作成
- 使い捨てスクリプト
- 不慣れな領域の探索
- 定型的なコード生成

## どんな場面で避けるべきか

- コアロジック
- セキュリティ関連
- パフォーマンスクリティカル
- 長期メンテナンスするコード

## バランスの取り方

1. Vibe Codingで素早く動くものを作る
2. 動作確認
3. 生成されたコードを読んで理解
4. 必要に応じてリファクタリング
5. テストを追加
